# 产品边界与路线

## 为什么叫 creator-to-curriculum

项目把创作者的内容库转化为学习课程。`creator` 比 `influencer` 更贴近知识创作者，`curriculum` 明确体现知识组织、学习顺序与教学设计。相比 `quick-learning-from-influencers`，名称更短，也不把“学得快”当作未经验证的承诺。

名称已确定为 **creator-to-curriculum**。CLI 为 `c2c`，Python 包为 `creator_curriculum`。

## 核心用户任务

“我信任这位创作者，想从他的内容中系统掌握某种能力，但不知道应该看什么、按什么顺序看、如何练习。”

一次成功交付要让学习者能够回答：

- 这个创作者主要教什么，各部分怎样关联？
- 我的目标需要哪些基础，适合从哪里开始？
- 每个知识点应看哪条视频的哪一段？
- 哪些视频在重复讲同一件事，哪些补充了条件、案例或例外？
- 创作者的可操作方法是什么，适用于哪些情境？
- 我该做什么练习，用什么产物判断是否学会？
- 有哪些内容没能获取、没能理解或仍需外部核实？

v0.1 的课件是可编辑的 Markdown 讲义。原始课件、参考书与外部资料保留来源身份；Agent 编写的练习与教学组织不冒充创作者原作。

## 关键概念

| 概念 | 含义 |
| --- | --- |
| 账号清单 | 某个时间、明确可见范围内发现的视频条目，包括失败与待处理条目 |
| 证据片段 | 带时间戳的字幕/转写；未来增加视觉证据 |
| 知识单元 | 有引用的概念、方法、案例或限制，可跨视频重复出现 |
| 主题 | 可归并多个知识单元的内容领域，标签相近不代表同一观点 |
| 课程模块 | 为某个学习目标组织的知识与练习，有先修关系 |
| 学习证据 | 学习者完成的解释、操作、作品或迁移任务，不是观看时长 |

## 从 video-learning 复用什么

保留它的采集、共享视频资产、时间戳转写、账号发现能力。当前通过只读适配器连接其已保存的清单与转写，不复制私有数据、账号配置或认证信息。

重新设计知识提取、跨视频归并、先修关系、课程与练习、掌握证据。账号定位、Hook、爆款模板、复拍方案不是本产品的学习目标。

## v0.1 的取舍

选择 Agent + 本地 CLI，先使整个证据链可以审阅和续做。当前 Agent 是推理执行者，CLI 不额外接入付费模型。普通用户不需要手写 JSON；Agent 负责按契约生成，CLI 拒绝无效结果。

知识提取按字符预算切分；主题索引与单独的主题文件支持逐步归并。v0.1 还没有并发 worker、任务锁或自动账号更新合并，同一工作区应串行写入。超大账号仍需 Agent 自行分批处理，实际成本取决于视频时长、转写服务和 Agent 的上下文用量。

保留每个非教学批次的理由，保留每条未纳入课程的知识及其原因。并不是所有视频都要进入主要学习路径，但所有已发现条目都应可追踪。

## 验收分层

1. **技术契约**：输入规范、引用存在、所有批次有状态、图无环、可重建；已用合成数据验证。
2. **来源完整性**：清单覆盖范围可解释，获取和转写失败有记录；需要具体平台账号验证。
3. **理解质量**：知识点忠于来源，归并没有抹平限制或分歧；需要抽查原视频。
4. **教学质量**：学习顺序合理，解释足够，练习能验证迁移；需要目标学习者实践。

技术测试通过不意味着第 2–4 层已经通过。

## 后续顺序

- 用一个真实博主完成可审阅的学习包，核查内容与学习顺序。
- 完成 YouTube / B 站的字幕与转写获取链路，以及中断恢复、增量清单合并。
- 引入画面证据，特别是操作步骤、公式、图表、演示和作者原始课件。
- 基于真实学习反馈迭代课程，再增加导出 PDF/PPTX、练习记录与复习计划。
- 有稳定的学习流程后，再考虑 Web 界面、多人共享和托管执行。

这些属于路线规划；不是当前已实现功能。
