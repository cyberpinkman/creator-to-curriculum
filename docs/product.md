# 产品边界与路线

## 名称与核心任务

项目名 **creator-to-curriculum**，CLI 为 `c2c`。这里的 curriculum 表示知识组织与学习顺序：用户通过创作者原作学习，项目帮助他们知道该看什么、先看什么、哪里可以查资料。

“我信任这位创作者，想从他的内容中系统掌握某种能力，但不知道应该看什么、按什么顺序看、怎样判断自己是否理解。”

## 默认交付：精细的学习导航

- 可点击知识地图：知识分组、先修关系、起步路径、后续节点。
- 学习需求：保存目标、已有基础、单次时间、学习方式和约束，未知与规划假设明确保留；默认 v2 计划绑定当前需求版本。
- 能力覆盖：映射目标需要的能力、已有来源、候选、缺失与分歧，能力缺口无需伪造视频。
- 学习活动：理解、操作、制作、比较、查阅五种方式，分别给出具体步骤、产物、自查、停止点、来源和必需资料。同一知识点可对应多个活动。原片时长与练习估算分开，不据此保证总时间适配。
- 学习路径：v2 用有稳定 ID 的步骤引用活动，说明阶段结果和安排理由；同一知识点可用于连续的不同活动。先修在前或明确声明已有基础，主动跳过仍保留能力缺口。旧 v1 路径维持不重复主题的兼容规则。路径声明不代表用户已掌握。
- 长视频定位：知识点显式关联原视频中的证据片段，完整视频证据仍可展开核对。引文时间是证据位置，不能冒充完整教学区间；平台不支持精确跳转时提示手动定位，不编造时间链接。
- 资料清单：作者原始课件、原视频画面摘录、外部补充、Agent 学习提示分别标识。公开可获取的文件由 Agent 下载，记录来源、时间、校验值；需要登录、付费或尚未发现的资料只索引状态。
- 本地 HTML、SVG 地图、Markdown 和 CSV 原视频索引；阅读器分别保存每条路径的当前学习步骤（v1 保存主题）、最近查阅主题、个人笔记，以及看过 / 练习 / 待复习 / 自报掌握四种状态，提供继续学习及记录导出 / 导入。开始任务或沿路径继续会更新学习位置，自由查阅不会覆盖它。
- 学习反馈：活动页保存独立的多次尝试、实际产物、产物来源和卡点。Agent 按每条活动标准给出有依据的反馈，提出继续、重试、回顾、换路径、补条件、补证据或收束当前活动的建议；用户明确采用后才调整位置，不自动改变四种个人标记。

标题、描述和合集是初始分类依据。为了精度，应按问题选择主线视频和模糊条目补查内容；不以全量转写为默认门槛，也不把“仅做索引”理解为只给几个粗略类别。独立课程、长讲义与完整转写是可选深度流程。

## 四类信息保持独立

| 层次 | 可以说明什么 | 不能推出什么 |
| --- | --- | --- |
| 清单与标题 | 此时此范围发现哪些作品、标题指向什么主题 | 已观看或正确理解内容 |
| 机器内容证据 | 转写或 OCR 的原片段与位置 | 人工核验、发音正确、动作安全、作者主张成立 |
| Agent 学习组织 | 主题、先修、建议观看顺序、观察问题 | 这些就是作者自己声明的课程体系 |
| 用户学习证据 | 实际复述、操作、迁移和疑问记录 | 自动以看完视频或生成材料算掌握 |

## 当前实现与边界

Agent 完成语义组织、资料检索与下载，Python CLI 完成共享契约校验、状态管理和导出。没有内置付费模型依赖。video-learning 提供账号发现和共享资产；本项目只读导入其快照，不复制凭据、账号配置或模仿报告。

`init-index / prepare-index / build-index` 是默认工作流。Agent 编写 v2 学习设计，CLI 校验当前需求与来源哈希、能力图、活动引用、必需资料和路径顺序，并生成准备条件报告。已有标题索引、主题证据关联、资料安全检查、离线地图与搜索继续使用。HTML 与 Markdown 使用同一份校验后的路径和任务。阅读界面以单个知识点为中心，使用分组目录、独立地图与资料视图；标题中的话题标签收进完整原题，逐字引文保留在可展开的内容定位中。移动端不依赖横向拖动地图，深浅色与字号设置只影响显示。

活动地址使用 `#study/<path>/<step>`，同一主题的不同活动可分别续接。主题地址使用 `#topic/<id>`，与记录页、资料页等内置页面分开，稳定主题 ID 不变。无歧义的旧主题地址仍可打开；旧地址与内置页面重名时优先打开内置页面。

默认工作区生成独立且稳定的身份，同一博主的独立工作区分别保存记录；重规划保留身份。个人记录与生成内容分离，以稳定 `package_id` 和主题 ID 存在浏览器本地存储；重生成或重排不会按位置错配。旧主题和旧路径记录保留并提示，不自动移到同名新主题。存储失败时明确显示尚未持久保存，仍可导出当前记录；未知版本或损坏记录不会被静默覆盖。写入前若发现记录已被另一个窗口改动，会停止覆盖，提示先导出本页记录再刷新；没有自动合并冲突。记录不随静态页面文件自动复制，没有账号或云同步。浏览器、协议、域名、端口或 `file://` 访问方式变化可能使用不同存储空间，迁移前应导出。

每条路径的学习位置由用户开始任务或明确继续来设置。旧记录只有最近查阅主题时，不据此猜测正在学习的任务。来源指纹覆盖原题、原分段及展示引文；来源变化后普通笔记和状态编辑不会消除核对提醒，需用户明确确认。指纹规则升级可能触发一次提示，旧标记继续保留；这种个人确认不是人工来源审核或掌握认证。

准备状态 ready / partial / blocked 只描述声明的输入是否齐全及可见缺口，不判断学习者掌握或来源真伪。旧 v1 包继续构建但显示 legacy；不会自动更改用户的需求、主题或历史记录。活动导航不会自动勾选任何学习状态。

反馈默认通过 `record-attempt / prepare-feedback / record-feedback` 贯通。浏览器记录可导出给 Agent，也可由 Agent 从用户明确提供的产物与卡点录入。CLI 生成交接输入、校验逐标准引文及观察依据、保留历史；提交或导入新尝试、录入反馈都会同步刷新阅读页中的反馈状态；刷新后不会继续把已被替代的建议显示为当前建议。静态页面不调用模型或自动评分，反馈导入必须经过共享校验。产物输入自动另存草稿，明确提交后才成为尝试；刷新可恢复，直接导出会保留并标明未提交草稿。采用回顾或换路径建议后，具体操作、产物和停止点会跟随到目标步骤，保留原反馈入口。

`met / needs_work / not_observed` 只描述本次产物在某条标准上的证据。无产物不等于失败，参考答案或 Agent 生成内容不能算学习者表现，协助完成不等于独立迁移。文件路径本身不证明文件已被查看；Agent 需记录实际观察方法和边界。完成比较活动也不会消除来源分歧，结束某个步骤不等于掌握整项能力。

尝试按路径、步骤、活动、标准和当前上下文绑定，不会因同主题而混用。同版本的新尝试或新反馈使旧建议失去当前采用资格，旧版本记录的迟到导入只保留历史；目标、计划、来源或本地必需资料文件变化后，原记录保留为历史。采用建议还会检查当前学习位置，不会把查阅另一步时的建议强行应用到当前任务。首版只导航到既有路径步骤，或给出具体补充动作；改变目标、拆分新活动等仍走需求与计划的正常重审流程。

浏览器中的尝试与采纳记录沿用本地导出/导入及跨窗口保护。Agent 导入工作区后的产物和反馈另存 `feedback-state.json`，生成页面会包含这些记录；普通导航演示不会凭空生成学习者记录，`--feedback` 演示使用显著标注的合成记录。

`prepare/synthesis/build` 保留分批深度提取与 Markdown 课程能力。OCR 片段可以导入；本项目不内置 OCR、ASR 或自动视听质量认证。

自动课件发现依赖 Agent 与可用来源工具，尚无通用全站下载器。链接存在不等于已下载，下载成功不等于教材内容已审阅，截图不等于作者原始课件。

## 验收与成本

分别检查技术契约、账号范围、语义忠实、实际学习可用性。技术测试不能替代语义抽查，语义抽查不能证明全量视频都已观看。每个案例说明数量、已知时长、未知时长、内容核对范围和资源状态。

API 响应的 token 独立保存，失败请求和重试同样计入。标题索引的成本主要随标题和描述文本量增长；关键视频核对随所读取的片段、模态和重试增长。总视频时长不是索引成本的充分预测变量。开发会话与每个账号的运行成本必须分开。

5 类仓库自写合成案例覆盖概念、操作、项目、观点比较和碎片查阅；测试同时覆盖需求变化、同主题多活动、能力缺口、来源分歧和必需资料不可用。它们验证架构与流程，不等于真实用户学习效果验证。

## 后续工作

增量刷新与合并、更多平台真实验收、可验证的视觉/音频定位和长期复习安排仍需完善。地图细分、资料章节 / 模板就地操作、统一搜索和全新环境首次真实采集验收是后续工作。托管服务、账号同步、自动测评以及 PDF/PPTX 导出不是当前能力。
